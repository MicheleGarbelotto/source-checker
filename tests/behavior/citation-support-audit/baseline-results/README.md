# Legacy citation-checker baseline

## Capture method and evaluation boundary

Status: **RED**.

This baseline records the actual first user-facing responses from five fresh, isolated agents executing the scenarios under the installed legacy `citation-checker` skill. These are captured agent outputs, not synthetic transcripts generated by the evaluator.

The exact prompts come from `../scenarios.yaml`. Each response below is reproduced verbatim. The available-material descriptions belong to the scenarios; the captured first responses do not establish that any document was opened, any mapping attempted, or any source passage verified.

Assertions use three outcomes:

- PASS: the captured response directly demonstrates the required intake behavior.
- FAIL: the captured response directly demonstrates an intake failure.
- NOT ASSESSED: the assertion requires execution or reporting that the first-response capture does not observe.

Statements of intended audit coverage and omissions from an introductory response are not evidence that document checks were completed or failed. Automatic mapping and all eight default-scope audit assertions are therefore NOT ASSESSED.

Questions and imperative information requests are both recorded. The assessed assertions concern observable input acceptance, clarification requests, permission gates, ambiguity handling, and the stated treatment of unavailable evidence.

The baseline is RED because of two observed intake failures:

1. The incomplete-corpus response requests permission before proceeding with the already-requested audit of accessible evidence.
2. The ambiguous-mapping response asks additional scope and style questions beyond the single material Garcia ambiguity.

These failures establish RED without scoring unobserved mapping, document checks, or reporting. The ambiguous-mapping failure uses the stated intake interpretation of “only”: only the material Garcia clarification should be requested. Under a narrower interpretation limited to mapping questions, that assertion would pass; the incomplete-corpus permission gate would still establish RED.

The counts are acceptance-assertion outcomes, not citation adequacy scores or estimates of model failure frequency.

### QMD/Zotero/PDF over-focus

These executions do not demonstrate a QMD or Zotero prerequisite. The underspecified response accepts `.qmd`, `.docx`, `.md`, and PDF targets and allows “another defined set” as the corpus. The DOCX response explicitly accepts DOCX and local PDFs without requesting conversion, Zotero, or a mapping manifest.

The responses use PDF and Zotero terminology, but that alone is not evidence of harmful over-focus. The scenarios themselves supply PDF source corpora. Automatic mapping is NOT ASSESSED because no file operation was observed; it must not be described as an observed limitation or failure.

### Inaccessible sources

The incomplete-corpus response recognizes a verified-subset route and assigns an Unverifiable treatment to Diaz-dependent claims. It does not misclassify inaccessible evidence as unsupported. However, it asks permission to proceed despite the audit already being requested. This observed permission gate is one of the two FAIL outcomes.

### Unnecessary scope questions

The DOCX, ambiguous-mapping, and default-scope responses ask whether potentially missing citations should be included. The ambiguous-mapping response also asks about style beyond the one material mapping ambiguity. The underspecified response requests sections, scope, and style in addition to the missing target and corpus.

These questions are observable intake behavior. Only the ambiguous-mapping assertion explicitly assessed here restricts clarification to the single material ambiguity. The other scope questions are recorded as observations rather than used to infer that later audit checks failed. The captures do not establish whether style could have been determined automatically.

### Verified-subset metrics

The incomplete-corpus response explicitly offers a “partial, verified-subset citation audit” and explicitly withholds whole-scope recall and precision. It does not explicitly mention numerical verified-subset recall and precision or their denominators.

That wording does not establish a reporting omission: the capture ended before an audit report was produced. Whether numerical subset metrics would be calculated remains unassessed. Similarly, the default-scope response contains no metric or coverage report, so both reporting assertions are NOT ASSESSED. Numerical correctness requires document evidence and observed audit execution.

The intended structural checks are:

- Parse `../scenarios.yaml` with the existing environment’s PyYAML.
- Confirm five unique IDs and one matching scenario heading per ID.
- Compare each exact-prompt block with its parsed YAML prompt.
- Confirm that all 20 YAML assertion strings occur verbatim in the appropriate tables.
- Confirm a PASS, FAIL, or NOT ASSESSED result and supporting explanation for every assertion.
- Confirm the aggregate count of 9 PASS, 2 FAIL, and 9 NOT ASSESSED.

No change to `scenarios.yaml` is required.

This record contains actual isolated-agent first responses. It assesses 11 observable intake assertions and leaves nine execution or reporting assertions unassessed. It is not evidence of completed audits, successful file access, PDF extraction, citation mapping, source-support classification, or numerical reporting. Commitments and omissions in an introductory response must not be substituted for observed execution.

The existing `.venv/` is validation infrastructure and is excluded from the task commit.
